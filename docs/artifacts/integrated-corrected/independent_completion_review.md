# Independent completion review

**Verdict: the requested pooled-versus-decentralized end-to-end research experiment is implemented, executed, and independently checked within its stated simulation scope. Its accuracy-preservation objective was unsuccessful.** Completing this experiment does not establish a production deployment or privacy protection.

The completed evidence comprises nine arms, three seeds, and 30 rounds per arm: 27 full-data runs on gpu003, each using all 50,000 training examples and all 10,000 test examples. The experiment trains heterogeneous adapters, applies the intended rank and weighting policies, exchanges updates over the peer graph, produces a final rank-16 model through a peer reduction, and compares it with ordinary rank-16 LoRA trained directly on the pooled training data.

| Requested component | Review finding |
|---|---|
| Conventional pooled baseline | Present, with persistent Adam moments; a separate reset-Adam control is also present. It uses the same alpha, frozen head/features, training union, and test set as the peer comparison. |
| Different client ranks and adaptive allocation | Present. The controller definitions are pinned to canonical P1 source, with ceilings 4/8/16, training-only probes, warm-up, floors, hysteresis, and quality recovery. The single-batch probe adaptation is explicit. |
| Domain-dependent contribution allocation | Present. The canonical P2 conservative factor function is imported; the five training-data/update features are provided through graph-delivered records. Factors demonstrably change weights and matrices. |
| Decentralized weighted training | Present as explicit neighbor-message simulation. Effective updates use `(alpha/r) B A`; the weighted Metropolis kernel preserves its stated stationary weights and detailed balance, rather than incorrectly enforcing a uniform mean. |
| Final assembly | Present as an actual simulated graph-restricted tree reduction to a predeclared capable peer, with one final SVD. A central all-client average is used only as a test oracle. Dense payload and memory costs are disclosed. |
| Whole-pipeline comparison and records | Complete. Per-round metrics, ranks, weights, matrices, payload ledgers, source/data hashes, summaries, paired contrasts, and figure inputs are retained. Final checkpoint files remain on the remote machine, with local hashes and verification records. |

`validation.json` records **3,460 passed checks** over the 27 completed runs, including paired data/initialization identities, capability limits, warm-up behavior, stochastic kernels, neighbor support, real domain interventions, and payload accounting. `smoke_validation.json` records **254 passed checks**. The final remote regression run, including policy guards and summary tests, records **463 passed tests in 17.90 seconds** in `regression.txt`.

A separate evaluator, `verify_saved_checkpoints.py`, imports no project training, aggregation, or evaluation modules. On gpu003 it independently reconstructs each saved model, evaluates the entire test set, and verifies initialization/cache identities, effective matrix rank, and prediction hashes. **All 27 recorded fp32 correct counts were reproduced exactly**, and all 27 final updates have numerical rank 16. A separate fp64 factorized calculation changes four near-tied predictions across 270,000 evaluations; only one changes an accuracy count, by 1/10,000 in seed 43/adaptive-quality. The initial stricter cross-precision failure and its detailed follow-up are preserved. No model or reported fp32 score was changed to obtain agreement.

The corrected result is decisive for the tested protocol: pooled accuracy is **57.23 ± 0.59%**, versus **6.90 ± 2.03%** for adaptive rank plus domain weighting, a paired difference of **−50.33 ± 2.46 percentage points**. The gap already exists in fixed-rank federated controls. Adaptive rank adds a paired loss against fixed feasible ranks; small domain-weight effects do not restore pooled accuracy. Domain-control traffic also dominates the factor-payload saving. These findings support a completed negative experiment, not a claim that every decentralized LoRA method is incapable of parity.

What remains outside this completed experiment is explicit: multi-host networking and failure tolerance; neighborhood-only automatic discovery; end-to-end backbone or language-model fine-tuning; medical-data validation; and any privacy guarantee or privacy-attack evaluation. The process has access to the full dataset, and domain-control allgather reveals supplied statistics and updates to participating peers. No hospital privacy or deployment-readiness claim follows from this completion review.

This review was performed by a separately delegated agent that audited the driver and policies and ran the independent checkpoint evaluator. The same agent also contributed the peer-assembly module and manuscript; this is an independent execution check within the project, not an external third-party audit.
